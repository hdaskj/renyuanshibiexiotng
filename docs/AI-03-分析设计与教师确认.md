# AI-03 相寻：相似人员照片推荐系统

## 1. 交互原型结论

本原型把“相似人员照片推荐”收窄为“用户在已明示授权的私人相册中寻找与自己或授权联系人有关的照片”。这一收窄直接回应课题的伦理要求，避免系统演变为公共场所监控、身份追踪或批量找人工具。

原型需要验证的核心不是“模型一定能识别谁”，而是完整产品闭环：授权前置、样本上传、多模态检索、结果解释、排序偏好、反馈纠错、撤回与数据清理。

原型入口：`index.html`

## 2. 用户与任务

### 目标用户

- 活动参与者：想在朋友共享的私人活动相册中找回自己的照片。
- 相册所有者：只希望已获授权的参与者检索指定相册。
- 系统管理员：负责索引状态、授权审计、模型版本和异常处理。

### 核心任务

用户知道自己曾参加某次活动，但只记得衣着、场景或大致外貌。系统根据上传样本及一句自然语言描述，在授权范围内返回可能包含该用户的照片，并说明推荐依据。

### 明确不做

- 不通过公众摄像头、公开网络或第三方爬取数据寻找陌生人。
- 不输出真实身份、联系方式、精确行踪或关系推断。
- 不允许绕过被摄者或相册所有者的授权进行批量检索。
- 不把视觉相似分称为“身份匹配概率”。

## 3. 关键需求

| 文档要求 | 原型呈现 | 后续工程实现 |
| --- | --- | --- |
| 照片上传与特征提取 | 上传、权利确认、三阶段提取状态 | InsightFace + CLIP/LLaVA 特征服务 |
| 人脸 + 衣着 + 场景检索 | 三因子排序、自然语言补充描述 | Milvus/Faiss 多向量召回与融合排序 |
| 推荐排序与解释 | 综合/人脸/衣着/场景排序；逐图证据解释 | 可解释加权模型、模板化解释生成 |
| 用户反馈闭环 | 相关/不相关、撤销反馈、反馈计数 | 去标识反馈表、离线训练、灰度回流 |
| 大规模向量库 | 授权相册和索引状态 | Milvus/Faiss 分区、索引调优 |
| 冷启动 | 自然语言描述和场景补充 | 视觉标签、活动上下文、规则召回 |
| A/B 测试 | 两组策略的召回、NDCG、响应时间 | 分流服务、实验埋点、统计显著性 |
| 响应时间小于 500ms | 原型显示 428ms 演示值 | P95 服务端监控，不含图片上传时间 |
| 明示同意、可撤回、禁止监控 | 首屏授权、管理授权、撤回后阻断 | 授权记录、删除任务、审计日志 |

验收指标中，Top-K 召回率和 NDCG 必须由正式数据和人工相关性标注计算；原型中的 86.4%、0.821 和 428ms 均为说明指标口径的演示值，不能作为算法结论。

## 4. 交互流程

1. 进入系统，阅读目的、范围、留存与禁止用途，完成明示同意。
2. 查看当前授权相册、有效期和样本留存策略。
3. 上传检索样本，确认合法使用权，等待特征提取。
4. 查看多模态召回结果，按综合、人脸、衣着或场景调整排序。
5. 输入自然语言描述，补充活动、衣着或场景线索。
6. 打开单张结果，查看三类证据及隐私声明。
7. 对结果进行相关/不相关反馈，必要时撤销反馈。
8. 在授权中心关闭单个相册或撤回全部授权。
9. 撤回后立即停止检索，并显示索引清理状态。

## 5. 交互设计决策

- 授权先于功能：首屏不可先浏览结果，明确同意按钮在勾选前保持禁用。
- 状态可感知：授权有效期、样本保留、检索范围始终可见。
- 结果不说成身份判断：统一使用“视觉相似”“建议”“证据”，不使用“确认某人”。
- 推荐可调节：用户可按人脸、衣着、场景改变侧重点，并可开启结果多样性。
- 解释可验证：每张结果展示人脸、衣着、场景三个分值及文字依据。
- 反馈可撤销：相关/不相关不是一次性动作，用户可以改正误操作。
- 撤回有后果：撤回后不只是隐藏界面，而是进入停止检索与索引清理流程。

## 6. 建议系统设计

### 前端

- React 实现照片网格、筛选、解释抽屉、授权中心和实验看板。
- 原型采用单文件 HTML 验证交互，正式项目迁移为 React 组件。

### 服务层

- Spring Boot 提供授权、相册、检索、反馈和审计 API。
- 检索接口先校验用户与相册授权关系，再调用特征服务和向量库。
- 样本文件仅在短期对象存储中处理，任务结束后异步删除。

### AI 与检索

- InsightFace 生成人脸/人体特征，CLIP 生成衣着与场景向量。
- 多向量分别检索后融合排序，输出可解释分值。
- LLaVA 等生成式模型只负责将结构化证据转为自然语言解释，不生成未经证据支持的身份结论。

### 索引与分区

- 向量索引必须按租户、授权相册和撤回状态分区。
- 撤回授权后先阻断查询，再异步删除向量和反馈关联。
- 审计日志保留必要操作记录，但不保留不必要的原始生物特征。

## 7. 隐私与伦理设计

- 明示同意：记录授权人、用途、范围、有效期和撤销入口。
- 可撤回：关闭相册授权或撤回全部授权后立即停止新检索。
- 最小化：检索样本不保存，不建立跨相册的人脸身份库。
- 用途限制：禁止监控、公开找人、身份核验和批量挖掘。
- 可解释：用户能看到推荐依据，避免把分数误认为事实。
- 审计：记录查询、授权变更、索引删除和模型版本变化。
- 数据主体权利：提供导出、删除、纠错和投诉入口。
