# AI-03 运行与数据库验证说明

## 1. 默认运行方式

默认配置用于课程演示，不需要 PostgreSQL 或 Milvus：

- 后端使用 H2 文件数据库：`backend/data/ai03`。
- 向量检索使用进程内 `local-demo-index`。
- 模型服务使用确定性特征桩，不保存原始图片。

H2 的 `schema.sql` 使用 `CREATE TABLE IF NOT EXISTS`，后端重启不会删除已有演示数据。需要全新演示库时，先停止后端，再显式重置 `backend/data/`。

启动模型服务：

```bash
cd model_service
python app.py
```

启动后端（JDK 17）：

```bash
cd backend
mvn spring-boot:run
```

启用清理 Worker，并缩短轮询时间以便本地观察任务状态：

```powershell
$env:CLEANUP_WORKER_ENABLED = "true"
$env:CLEANUP_WORKER_SIMULATION = "true"
$env:CLEANUP_POLL_INTERVAL_MS = "500"
```

启动 React 客户端：

```bash
cd frontend/app
pnpm install
pnpm dev
```

访问 `http://127.0.0.1:5173/`。开发登录账号为 `participant`、`owner` 和 `admin`。

## 2. 数据库验证

核心表包括：

- 身份与相册：`users`、`albums`、`album_members`
- 授权流程：`search_requests`、`consents`
- 检索过程：`search_sessions`、`search_results`
- 结果闭环：`feedback_events`、`audit_events`
- 隐私清理：`deletion_jobs`、`outbox_events`

关键完整性规则：

- 申请、授权、会话、结果、反馈、审计和清理任务都有状态或关联约束。
- 同一会话内的 `photo_id` 和 `rank_number` 唯一。
- 分值限制在 0 到 100。
- 同一授权对应的删除资源唯一，避免重复清理任务。
- 删除任务默认最多尝试 5 次，失败后指数退避；达到上限标记为 `FAILED`。
- 清理任务领取带 120 秒租约，进程崩溃后可被超时回收，不会永久停留在 `RUNNING`。

健康检查：

```bash
curl http://127.0.0.1:8081/api/v1/health
curl http://127.0.0.1:8081/api/v1/health/dependencies
```

运行完整冒烟测试：

```bash
python scripts/e2e_smoke.py
```

该脚本覆盖申请、审批、授权、检索、结果落库、反馈、审计、撤回、重复撤回幂等、清理任务和 outbox 发布。

## 3. PostgreSQL

启动课程联调用 PostgreSQL：

```bash
docker compose -f infra/postgres-compose.yml up -d
```

后端使用 PostgreSQL profile：

```bash
cd backend
SPRING_PROFILES_ACTIVE=postgres \
DB_URL=jdbc:postgresql://127.0.0.1:5432/ai03 \
DB_USER=ai03 \
DB_PASSWORD=ai03 \
mvn spring-boot:run
```

Flyway 会依次执行 `V1` 到 `V5`。当前工作区没有 Docker/PostgreSQL 运行时，因此 PostgreSQL 外部实例联调仍需在具备该环境时执行；H2 下的结构、种子、重复启动和完整业务链路已验证。

## 4. 当前边界

- 清理 Worker 在 `CLEANUP_WORKER_SIMULATION=true` 时只验证任务状态机；真实对象存储、缓存和 Milvus 删除适配器尚未接入。
- 开发登录令牌是内存令牌，生产环境应替换为 OIDC/JWT。
- 模型服务仍是可替换桩，正式版本需要接入 InsightFace、CLIP 和受证据约束的解释模型。
